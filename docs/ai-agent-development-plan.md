# AI 智能体自研开发计划

## 1. 开发原则

这是一个学习型项目，但工程标准不能降低。每个阶段都需要：

- 明确目标。
- 可运行结果。
- 实现步骤。
- 测试和验收。
- 架构更新。
- 可回退方案。

不按“先把所有功能写完”的方式开发，而是按一条完整、可验证的业务链路逐步扩展。

## 2. 总体路线

```text
接口盘点
  -> 技术选型
  -> 最小聊天与 SSE
  -> 身份和权限
  -> 前端交互知识与客户端动作
  -> 只读工具
  -> Agent Runtime
  -> 审批、幂等和审计
  -> RAG 与报告
  -> 测试评测
  -> 部署运维
```

## 3. 阶段 0：接口和能力盘点

### 目标

确认原后端在不修改接口的前提下，哪些业务能力可以被 Agent 安全复用。

### 步骤

1. 收集项目、设备、航线、任务、缺陷、媒体和报告接口。
2. 记录接口认证方式、权限、参数、返回结构和错误码。
3. 标注查询、草稿、写入和设备控制风险。
4. 确认哪些接口支持幂等或可以生成幂等。
5. 列出缺失能力，不在 Agent 中伪造。

### 产出

- 原后端接口清单。
- 工具候选表。
- 权限矩阵。
- 禁止动作清单。
- 需要补充文档或后端接口的问题列表。

### 验收

- 每个工具都有对应原后端接口。
- 写操作都有用户身份、权限、确认和幂等方案。
- 无法安全实现的能力被明确排除。

## 4. 阶段 1：技术选型和仓库初始化

### 目标

建立 Vue 3 + Fastify + TypeScript 的最小全栈工程。

### 选型总结

| 项目 | 选择 | 原因 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript | 已有技术基础，组件化清晰 |
| Node 框架 | Fastify | 轻量、类型友好、SSE 易控制 |
| 校验 | Zod | 输入输出和工具 Schema 共用 |
| 模型 | DeepSeek | 按当前官方能力接入 |
| 状态 | Redis | 运行、锁、限流 |
| 持久化 | PostgreSQL | 会话、运行、审批、审计 |
| 向量 | pgvector | 统一 PostgreSQL 运维 |

### 步骤

1. 统一 Node 和 pnpm 版本。
2. 建立 workspace。
3. 创建 Vue 3 和 Fastify 应用。
4. 增加环境变量 Schema、统一错误、日志和优雅停机。
5. 增加健康检查和 CI 质量门禁。

### 验收

- 本地可以启动前后端。
- 缺失配置会导致服务启动失败。
- 主分支可以格式化、类型检查、测试和构建。

## 5. 阶段 2：最小聊天、SSE 和 DeepSeek

### 目标

让用户在 Vue 页面输入问题，经 Fastify 调用 DeepSeek，并通过 SSE 看到流式回答。

### 步骤

1. Vue 建立对话输入和消息列表。
2. Fastify 提供创建 run 和订阅 SSE 的接口。
3. Node 配置 DeepSeek Key 和模型客户端。
4. 定义 `response.delta`、`run.completed` 和 `run.failed` 事件。
5. 记录模型、Token、耗时和 requestId。

### 验收

- Key 不出现在浏览器。
- SSE 能正常关闭和重连。
- 模型失败有稳定错误码。

## 6. 阶段 3：身份、租户与权限

### 目标

Agent 继承真实用户权限，原后端仍然是最终授权者。

### 步骤

1. Vue 携带登录凭证请求 Fastify。
2. Fastify 建立用户上下文，不把 Token 传入 Prompt。
3. Backend Adapter 使用用户凭证访问原后端。
4. 建立项目成员和资源权限测试。
5. 权限变化时清理前端缓存和运行上下文。

### 验收

- 伪造项目 ID、任务 ID 和设备 ID 无法越权。
- 不使用管理员服务账号代理所有用户。
- 权限拒绝有稳定错误码。

## 7. 阶段 4：前端交互知识与客户端动作

### 目标

让 Agent 知道用户当前所在的页面、可执行的前端操作和应该展示的界面状态，同时不让模型直接生成 JavaScript。

### 步骤

1. 整理页面、路由、权限和用户操作流程。
2. 为每个页面动作定义 ID、参数 Schema、前置条件和结果。
3. 建立 `ui-action-manifest.json` 或等价动作清单。
4. Vue 3 实现动作注册表，只执行白名单动作。
5. 把交互文档按页面、动作和状态切片进入 RAG。
6. CI 校验动作清单、路由和权限是否一致。

### 产出

- 前端交互知识文档。
- 页面动作清单。
- Vue 客户端动作注册表。
- `client.action` SSE 事件协议。
- 交互动作与 Server Tool 的映射表。

### 验收

- 模型不能输出任意 JavaScript 或 DOM 选择器。
- 未注册动作会被前端拒绝。
- 打开表单和创建业务数据严格分离。
- 无权限动作不会出现在可用动作列表中。

## 8. 阶段 5：只读工具系统

### 目标

把项目、任务、设备、缺陷和报告查询封装成工具。

### 步骤

1. 定义工具契约。
2. 实现 Backend Adapter。
3. 标准化和裁剪原后端结果。
4. 实现工具调用记录和错误映射。
5. 建立 20 条真实问题和工具选择评测。

### 验收

- 模型不能调用未注册工具。
- 工具参数经过 Zod 和权限校验。
- 答案能引用原始记录。

## 9. 阶段 6：Agent Runtime

### 目标

把一次模型调用升级成有状态、有边界、可恢复的运行流程。

### 步骤

1. 建立 run 和 step 数据模型。
2. 实现规划、工具执行和结果回传循环。
3. 增加最大轮数、工具数、超时和取消。
4. 使用 Redis 保存短期状态。
5. 使用 PostgreSQL 保存运行和审计。

### 验收

- 页面断线不影响运行。
- 重复工具调用能被识别。
- 运行可以查询、恢复和取消。

## 10. 阶段 7：确认、幂等和审计

### 目标

让高风险操作安全地影响真实业务。

### 步骤

1. 为写工具建立 `prepare` 和 `commit`。
2. Vue 显示确认卡片。
3. 确认记录带用户、参数、风险和过期时间。
4. commit 使用幂等键并重新校验资源状态。
5. 记录原后端 requestId、错误和业务结果。

### 验收

- 未确认不执行。
- 确认过期不能执行。
- 重复提交不重复创建任务。

## 11. 阶段 8：记忆、RAG 和报告

### 目标

让 Agent 能理解 SOP、法规和历史报告，并生成可追溯的结果。

### 步骤

1. 建立文档解析、切片和元数据。
2. 使用 pgvector 存储向量。
3. 检索前做租户和项目权限过滤。
4. 返回引用、页码和原文片段。
5. 长报告使用队列和 Worker 生成。

### 验收

- 实时业务状态仍通过工具查询。
- 引用可以回到原文。
- 报告生成不影响同步对话体验。

## 12. 阶段 9：测试、评测和生产治理

### 目标

把 Agent 从可运行升级为可发布、可观察、可回滚的系统。

### 步骤

1. 建立单元、集成、契约和端到端测试。
2. 建立 Golden Dataset 和红队用例。
3. 增加 Trace、费用、首 Token 和工具成功率指标。
4. 增加用户、项目和模型配额。
5. 设计模型故障、缓存故障和原后端故障降级。
6. 进行容器化、CI/CD、迁移和回滚演练。

### 验收

- 权限泄漏和重复写入用例为零失败。
- 能定位一次失败的模型和工具链路。
- 模型不可用时原平台业务不受影响。
- 可以在预算内灰度发布和回滚。

## 13. 如果自己学习，推荐的第一个月顺序

### 第 1 周

- Node 事件循环、HTTP、Fastify 路由和插件。
- Vue 请求 Fastify。
- SSE 最小流式页面。

### 第 2 周

- DeepSeek API、Prompt 分层和结构化输出。
- 一个只读工具。
- 工具参数校验和错误处理。
- 页面动作清单和 Vue 客户端动作注册表。

### 第 3 周

- Agent Runtime 状态机。
- Redis 运行状态。
- PostgreSQL 运行、工具调用和审计。

### 第 4 周

- prepare/commit 写工具。
- 审批卡片、幂等和失败恢复。
- Golden Dataset、测试和可观测性。

## 14. 最终交付物

- 可运行的 Vue 3 智能体工作台。
- 可运行的 Fastify Agent BFF。
- 原后端 Adapter 和工具注册表。
- 前端交互知识文档和 `ui-action-manifest.json`。
- Vue 3 客户端动作注册表。
- DeepSeek 模型适配器。
- Agent Runtime 状态机。
- 会话、运行、审批和审计数据模型。
- 架构文档、ADR、工具契约和 Runbook。
- 测试集、评测集和故障演练记录。
